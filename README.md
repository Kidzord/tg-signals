# Сигналы KidzordFx → Telegram

Сервис принимает вебхук от TradingView, рисует карточку сделки и публикует её в группу.
Раз в день по расписанию отправляет продающий пост.

```
TradingView (alert() индикатора)
        │  webhook: "LONG XAUUSD 15 | вход … | SL … | TP1 … | TP2 … | TP3 …"
        ▼
   /tv/<секрет>  ──►  парсер  ──►  MT5 (OHLC)  ──►  PNG 1280×720
        │                                              │
        └──────────────► Telegram sendPhoto ◄──────────┘
                         + дневной пост по cron
```

Скриншот TradingView не используется намеренно: вебхук не умеет передавать изображение,
а рендер собственных свечей по данным брокера заодно снимает вопрос с правами на чужие графики.

---

## Бот без TradingView (основной путь)

Запуск — только через `bot.bat`, не через `python bot.py`.
Причина: у `python` в системе может оказаться версия 3.15, а пакет `MetaTrader5`
под неё не собирается вообще (нет колеса). `bot.bat` сам находит интерпретатор,
в котором MetaTrader5 есть, и пишет какой именно выбрал.

Индикатор можно вообще не подключать к TradingView: бот сам считает ту же логику
по барам MT5 и сам публикует сигналы. Ни вебхука, ни публичного адреса, ни подписки
TradingView для этого не нужно.

```
MT5 (терминал на том же ПК)
      │  M15 + H1 + H4 + D1 + W1
      ▼
  strategy.py — чек-лист из 12 пунктов, уровни, стоп, цели
      ▼
  bot.py — новый закрытый бар → карточка → Telegram
```

| Команда | Что делает |
|---|---|
| `bot.bat` или `python bot.py` | цикл: опрос MT5 каждые 20 секунд |
| `python bot.py once` | одна проверка и печать чек-листа |
| `python bot.py scan` | прогон по истории: сделки, R, сверка с графиком |

Публикуется карточка входа, затем сообщения о TP1 / TP2 / TP3 и стопе.
Одна сделка за раз — как в индикаторе.

**Важно:** бот повторяет исправленную версию индикатора (`KidzordFx_V1_fixed.pine`).
Если на графике осталась исходная, сигналы разойдутся: там четвёртый фактор SMC —
«диапазон», а здесь «дисконт/премиум».

Сверка: `python bot.py scan` печатает последние сделки с временем входа. Сравни
3–5 из них с графиком: если время и сторона совпадают — порт верный.

Настройки в `.env`: `BOT_SYMBOL`, `BOT_TF`, `BOT_POLL_SEC`, `BOT_BARS`, `BOT_DRY`.
`BOT_DRY=1` — ничего не отправлять, только печатать.

## Быстрый старт

### 1. Бот и группа

1. `@BotFather` → `/newbot` → получи токен вида `123456:AA...`.
2. Добавь бота **в группу как администратора** (иначе он не сможет писать).
3. Напиши в группе любое сообщение, затем открой:

   ```
   https://api.telegram.org/bot<ТОКЕН>/getUpdates
   ```

   Найди `"chat":{"id":-100...}` — это и есть `TG_CHAT_ID`. У супергрупп он начинается с `-100`.

### 2. Конфиг

```bat
copy .env.example .env
```

Заполни `TG_BOT_TOKEN`, `TG_CHAT_ID`, `WEBHOOK_SECRET` (любая длинная строка), поправь `PROMO_TEXT`.

Если не хочется искать `chat_id` вручную — заполни только токен и запусти:

```bat
python app.py findchat
```

Скрипт покажет все чаты, где уже есть бот, и сам впишет единственную группу в `.env`.
Затем проверь доставку:

```bat
python app.py test
```

### 3. Проверка без сети

```bat
python app.py selftest    :: разбор трёх форматов алерта
python app.py demo        :: карточка в samples\sample_signal.png
python app.py preview     :: текст поста и его длина
```

### 4. Запуск

```bat
python app.py
```

Сервис слушает `http://0.0.0.0:8080`, проверка — `http://localhost:8080/health`.

### 5. Публичный адрес

TradingView должен достучаться до сервиса по HTTPS. Для теста хватит туннеля:

```bat
cloudflared tunnel --url http://localhost:8080
```

Получишь `https://что-то.trycloudflare.com`. Адрес вебхука:

```
https://что-то.trycloudflare.com/tv/<WEBHOOK_SECRET>
```

У бесплатного quick-туннеля адрес меняется при каждом перезапуске — для постоянной работы нужен
named tunnel, VPS или проброс порта.

Собрать готовый адрес вебхука (с секретом) одной командой:

```bat
python app.py url https://что-то.trycloudflare.com
```

Если `cloudflared` не установлен, бинарник лежит в `bin\cloudflared.exe` — запускай его напрямую.

## Настройка алерта в TradingView

1. Индикатор на графике → **Alert** (будильник).
2. **Condition** → выбери индикатор → **Any alert() function call**.
3. Включи **Webhook URL** и вставь адрес из шага 5.
4. Поле сообщения оставь по умолчанию — текст берётся из `alert()` внутри индикатора.
5. Сохрани. Индикатор уже вызывает `alert()` при входе в сделку с частотой `once_per_bar_close`.

Вебхуки доступны на платных тарифах TradingView. На бесплатном их нет — тогда либо апгрейд,
либо отдельный модуль на email-алерты (скажи, соберу).

Проверка вручную, без TradingView:

```bat
curl -X POST "http://localhost:8080/tv/<WEBHOOK_SECRET>" ^
  -d "LONG XAUUSD 15 | вход 4000.12 | SL 3988.72 | TP1 4011.52 | TP2 4022.92 | TP3 4034.32"
```

Ответ `{"ok":true,...}` и пост в группе означают, что вся цепочка рабочая.

## Дневной пост

`PROMO_ENABLED=1`, время `PROMO_TIME` в часовом поясе `PROMO_TZ`. Текст — `PROMO_TEXT` в `.env`,
переносы строк через `\n`, HTML-теги Telegram (`<b>`, `<i>`, `<a href>`) поддерживаются.

Проверить текст и отправить прямо сейчас:

```bat
python app.py promo
```

## MetaTrader 5

Терминал должен быть **запущен и залогинен** на том же компьютере, где работает сервис.
Логин и пароль никуда передавать не нужно: пакет подключается к уже открытому терминалу
и только читает бары — торговых операций в коде нет.

Установка пакета (один раз):

```bat
python -m pip install MetaTrader5
```

Проверка связки:

```bat
python app.py mt5test
```

Команда печатает терминал, маскированный номер счёта, список «золотых» символов брокера
и три последних бара M15. Расшифровка ошибок:

| Сообщение | Что делать |
|---|---|
| `пакет не установлен` | `pip install MetaTrader5` |
| `Authorization failed (-6)` | терминал запущен, но не залогинен: **File → Login to Trade Account** или **File → Open an Account → Demo** |
| `IPC timeout` | терминал закрыт или Python и MT5 на разных машинах |
| `бары не получены` | символ не в Market Watch — добавь его вручную |

Если у брокера тикер с суффиксом (`XAUUSD.r`), укажи `MT5_SUFFIX=.r` в `.env`.

Терминал должен работать постоянно, пока работает сервис — иначе карточки уйдут
на демо-данных. Для тестов достаточно демо-счёта: цены те же, риска нет.

### Если нет MetaTrader 5

Карточка берёт свечи в таком порядке:

1. **MT5** — терминал должен быть запущен и залогинен на том же компьютере, где работает сервис.
   Если у брокера суффикс в тикере (`XAUUSD.r`), укажи `MT5_SUFFIX=.r`.
2. **CSV** — путь в `DATA_CSV`, колонки `time,open,high,low,close,volume`.
3. **Демо-данные** — если нет ни того, ни другого. На карточке будет водяной знак «ДЕМО».

Пока источник — демо, постить в платную группу нельзя: цифры не настоящие.

Установка MT5-модуля (Windows, терминал уже стоит):

```bat
pip install MetaTrader5
```

## Развёртывание

**Windows, постоянно включённый ПК.** Автозапуск через Планировщик задач: действие
`python C:\путь\app.py`, «Выполнять при входе в систему». Питание — без сна.

**VPS (Ubuntu).** `systemd`-юнит:

```ini
[Unit]
Description=KidzordFX signals
After=network.target

[Service]
WorkingDirectory=/opt/tg-signals
ExecStart=/usr/bin/python3 app.py
Restart=always
EnvironmentFile=/opt/tg-signals/.env

[Install]
WantedBy=multi-user.target
```

На VPS MT5 не будет (это Windows-терминал) — там нужен CSV или внешний источник данных.

## Правила и риски

- **Продажа доступа.** На TradingView механизм — invite-only скрипты; условия доступа
  проверь в актуальных правилах платформы, они меняются. Публиковать чужой код под своим именем нельзя.
- **Графики.** Мы рисуем свои свечи, а не скриншоты TradingView — это осознанно.
- **Обещания доходности.** В постах нет цифр прибыли, только уровни. Если начнёшь публиковать
  результаты — публикуй и убыточные сделки, иначе это реклама с недостоверными сведениями.
  Держи публичный журнал сигналов: он же снимает половину претензий.
- **Задержка.** Алерт срабатывает на закрытии бара. Подписчик видит пост через несколько секунд,
  и цена уже может уйти. Поэтому в посте есть конкретная цена входа — фиксируй её в журнале.
- **Доступность.** Если компьютер уснул или упал туннель, сигнал не уйдёт молча. Для платного
  продукта нужен VPS и мониторинг `/health`.
