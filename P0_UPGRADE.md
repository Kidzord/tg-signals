# P0: что изменилось и что сделать руками

Этот файл — короткая инструкция к изменениям, которые нельзя сделать кодом:
ротация токена, внешний мониторинг и первый запуск новой схемы.

## 1. Обязательно: ротировать токен бота

Токен `8957215002:AAG...` был захардкожен в `reminder_scheduler.py` и
`send_remind.py` и лежит в истории git с первого коммита. Из исходников он
убран, но старый токен всё ещё действителен.

1. Открой @BotFather → `/mybots` → нужный бот → **API Token** → **Revoke current token**.
2. Положи новый токен в `.env` (`TG_BOT_TOKEN` и/или `SUB_BOT_TOKEN`).
3. Перезапусти ботов (`start_all.ps1`).
4. По желанию вычисти старый токен из истории git:
   `git filter-repo --replace-text <(echo '8957215002:AAG...==>REDACTED')`
   Это переписывает историю — делай только если понимаешь последствия.

Проверка, что в рабочем дереве токенов больше нет:

```bat
python -m pytest -q tests/test_core.py::test_no_hardcoded_telegram_tokens
```

## 2. Запуск новой схемы

```bat
start_all.ps1
```

Что изменится:

* `reminder_scheduler.py` больше не запускается (в нём был токен и он дублировал
  напоминания). `start_all.ps1` сам остановит старый процесс.
* `scheduler.bat` теперь запускает `autoposts.py`: утренний план, итог дня,
  итог недели, промо, напоминания Threads/X, карусели TikTok и недельный
  отчёт по деньгам.
* `monitor.bat` — новый процесс: проверяет пульс `bot.py`, очередь доставки и
  пингует внешний dead-man switch.
* `watchdog.ps1` — раз в 5 минут вызывает `start_all.ps1` и поднимает упавшее.

Проверка без отправки сообщений:

```bat
python monitor.py once
python -m pytest -q
```

## 3. Внешний dead-man switch (руками, 2 минуты)

Локальный `monitor.py` не поможет, если упал весь ПК. Нужен внешний сервис:

1. Зарегистрируйся на healthchecks.io (или Uptime Kuma / cron-job.org).
2. Создай check с периодом 5–15 минут.
3. Скопируй ping URL в `.env`:

```ini
HEALTHCHECK_URL=https://hc-ping.com/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

Можно не открывать файл: `python monitor.py set-healthcheck https://hc-ping.com/...`
запишет URL и сразу проверит его пингом.

В этом проекте URL уже прописан 2026-11-02 (значение — только в `.env`),
`monitor.py` перезапущен и пингует сервис каждый цикл.

Пока ПК жив, `monitor.py` пингует URL; если пингов нет — сервис шлёт алерт.

## 5. Что теперь работает иначе

* **Premium получает результаты сделок.** Раньше TP1/TP2/SL уходили только в
  бесплатную группу. Теперь подпись карточки входа редактируется:
  `✅ TP1 взят · +1.0R · всего +1.0R`, затем `🛑 Стоп · итог ...`.
* **Результат не обгоняет вход в бесплатной группе.** Если сделка закрылась
  раньше, чем истекла `FREE_DELAY_SEC`, результат ждёт отправки входа.
* **Доставка переживает перезапуск.** Очередь в `state.db` (SQLite), у каждой
  строки свои попытки, `429 retry_after` и обработка блокировки бота.
* **Оплаты идемпотентны.** Повторный вебхук Stars или повторный `getInvoices`
  не продлит подписку дважды. Возвраты Stars обрабатываются.
* **Фильтры подписчика:** `/symbols XAUUSD,AUDUSD`, `/symbols all`,
  `/maxday 3`, `/maxday 0`.
* **Промокоды:** `/promo КОД`.
* **Трек-рекорд:** `/stats` теперь показывает PF, максимальную просадку и
  equity-картинку; итог недели в канале тоже содержит PF/DD.

## 6. Что важно не удалять

`state.db` — это очередь доставки и журнал платежей. Если удалить файл,
подписчики не получат результаты по открытым сделкам, а история оплат
потеряется (доступ в `users.json` останется). Делай резервную копию
`state.db`, `users.json` и `trades.jsonl`.
