# Этап 0: метрология WFA (2026-11-04)

Отчёт по §1 плана `docs/RESEARCH_PLAN_2026-11-04.md`. Цель — сделать так,
чтобы прогоны разных стратегий и фидов можно было сравнивать между собой.

## Что изменено

| Что | Где | Как теперь |
|---|---|---|
| Издержки | новый `costs.py` | `cost_r = max(0.05R, спред/риск)` на сделку; спред символа из `WF_SPREAD_<SYM>` / `WF_SPREAD`, иначе `symbol_info`; пол 0.05R при нулевом спреде |
| WFA | `tools/walk_forward.py` | издержки по каждой сделке, а не плоские 0.05R; `--stress N` (спред ×N), `--delay N` (вход на N баров позже), `--shift-hours N`, `--rebuild-htf` |
| Вердикт | новый `wfa_verdict.py` | `net_R > 5` и `folds_active >= 8` и `доля активных в плюсе >= 60%` и `avg_R > 0.05`; один код для консоли и реестра |
| Плато | `tools/walk_forward.py` | для прошедшего кандидата печатаются соседи по сетке (±1 шаг одного параметра) на тех же OOS-окнах; смена знака = «НЕ ПРОХОДИТ (плато)» |
| Реестр | `research.py`, `config.py` | хранит `folds_active`, `folds_active_positive`, `folds_active_share`; ворота используют ту же формулу; старые записи без новых полей трактуются как «все фолды активны» |
| Стратегии в WFA | `tools/walk_forward.py` | добавлены `pdl` (9 комбинаций) и `crt` (4); `RANGE_MAX_STOPS` и env-параметры PDL проброшены в прогон |
| Live-бэктесты | `bot.py` | `scan_*` печатают net после `costs.summary`; `bot.simulate(..., entry_delay=N)` поддерживает execution stress |

Единая модель издержек вычитается один раз на полный проход (вход-выход).
`stress=2` удваивает спред, но не пол 0.05R.

## Что это значит

1. **Classic native проходит по новой метрике и держит спред ×2.**
   Это первый кандидат, проверенный единым измерителем; live-решение не
   меняется — classic уже работает только на native.
2. **Задержка входа на один бар убивает classic: +15.34R → −29.05R.**
   Спред ×2 стоит всего −2R, а 15 минут ожидания — −44R. Это не аргумент
   против стратегии: live входит сразу после закрытия бара, задержка там
   секунды. Но это значит, что edge живёт в закрытии сигнального бара, и
   повторный вход «через бар», ручной вход по факту поста или исполнение
   с лагом в 15 минут его не сохраняют. Для classic любой перенос входа
   (лимитка, ожидание ретеста, отложенный пост) нужно проверять отдельно.
3. **Сдвиг сессий на +1 час почти не меняет net (+15.34 → +15.66R), но
   роняет вердикт: 13/23 (57%) вместо 15/24 (62%).** То есть эдж не
   привязан к таймстампу брокера, но доля активных фолдов ходит вокруг
   порога 60% на один фолд. Для classic это значит: вердикт «ПРОХОДИТ» на
   базовом прогоне — не запас прочности, а равенство на границе; решение
   по-прежнему должно опираться на net R, два фида и форвард.
4. **Classic на Exness после пересборки HTF: −3.20R.** Диагностика
   `tools/classic_feed_diag.py` на всём окне с live-параметрами давала +0.24R.
   Расхождение — не издержки (они 3.55R при 71 сделке), а выбор параметров
   на 60-дневных окнах. Формально критерий этапа «тот же знак на двух фидах»
   не выполнен: знак отличается при разнице в 3R, то есть в пределах
   микроструктурного шума M15 Exness (0…+7R по прошлой диагностике).
   Вывод «classic только на native» остаётся.
5. **PDL, CRT и sonar закрыты честным WFA.** Все три в минусе после издержек
   на золоте; PDL и CRT записаны в `research.json` как tested с вердиктом
   «НЕ ПРОХОДИТ». Это не приговор идеям на других символах, но на XAUUSD
   они больше не висят в неопределённости.
6. **Числа в `docs/VALIDATION_2026-11-04.md` несопоставимы с новыми**:
   там доля считалась по всем фолдам и издержки были плоские. В шапке того
   документа добавлена пометка.

## Как повторить

```bash
# native
MT5_TERMINAL_PATH="C:/Program Files/MetaTrader 5/terminal64.exe" \
BOT_SYMBOL=XAUUSD WF_BARS=30000 python tools/walk_forward.py classic

# cost stress
... python tools/walk_forward.py classic --stress 2

# второй фид: сдвиг сессии и пересборка HTF из M15
MT5_TERMINAL_PATH="C:/MT5-Exness/terminal64.exe" \
BOT_SYMBOL=XAUUSDm WF_BARS=30000 \
python tools/walk_forward.py classic --shift-hours 2 --rebuild-htf

# проверка артефакта таймстампа без пересборки HTF
... python tools/walk_forward.py classic --shift-hours 1
```

Спред можно зафиксировать на повторяемом прогоне: `WF_SPREAD_XAUUSD=0.22`,
`WF_COST_STRESS=2`. На закрытом рынке MT5 отдаёт нулевой спред, поэтому
без `WF_SPREAD` работает пол 0.05R.

## Что осталось за этапом 0

- `sonar` не записан в `research.json` — идеи в реестре не было; вердикт
  зафиксирован только в этом отчёте.
- Execution stress показал, что classic держится на закрытии сигнального
  бара: перед этапом 1 нужно отдельно проверить live-латентность (время от
  закрытия бара до отправки сигнала и входа) на реальных сделках.
- Сетки этапа 1 (ER, стопы, ADX, сессии) не трогались: сначала метрология,
  теперь можно перебирать по 3–5 pre-registered осей.
