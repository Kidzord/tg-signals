# Внешние источники: идеи и консенсус

Два легальных способа использовать чужие Telegram-каналы. Оба исключают
автоматическое чтение каналов: Bot API видит только каналы, где бот админ,
а userbot по MTProto нарушает правила Telegram и может привести к бану номера.

## 1. Донор идей (`research.py`)

Чужой сигнал — не повод его ретранслировать, а гипотеза, которую надо
проверить на своих данных. Реестр фиксирует источник, ведёт идею по статусам
и не пускает её дальше без пройденного walk-forward.

```
idea → testing → tested → promoted | rejected
```

### Рабочий цикл

1. **Зафиксировать идею.** Источник обязателен — без атрибуции идея не
   принимается:

   ```
   python research.py add --title "Sweep PDH/PDL" --source "@channel" \
       --url https://t.me/channel/123 --hypothesis "снятие дневного максимума даёт возврат" \
       --symbols AUDUSD,USDCAD --tf 15
   ```

2. **Реализовать правило** в отдельном модуле (`pdl_sweep.py`, `crt.py`, …).
   Правила фиксируются в `docs/` до прогона, чтобы результат нельзя было
   подогнать под статистику автора.

3. **Прогнать WFA** тем же протоколом IS → OOS, что и остальные стратегии:

   ```
   python research.py wfa <id> --strategy range --symbol AUDUSD
   ```

   Команда вызывает `tools/walk_forward.py --json` и записывает числа в реестр.
   Нужен запущенный терминал MT5. Вручную: `python research.py record <id>
   --strategy range --symbol AUDUSD --trades 42 --net-r 18.5 --folds 5/7`.

4. **Пройти ворота.** `python research.py promote <id>` разрешён только если:
   вердикт `ПРОХОДИТ`, сделок не меньше `RESEARCH_MIN_TRADES`, net R > 0 и доля
   фолдов в плюсе не ниже `RESEARCH_MIN_POS_FOLDS`.

5. **Решение записывается в журнал** `docs/RESEARCH_LOG.md`. Promotion — это
   запись решения, а не деплой: конфиг бота и состав флота по-прежнему меняет
   человек.

### Команды

| Команда | Назначение |
|---|---|
| `add` | зарегистрировать идею с источником |
| `list [--status]` | список идей |
| `show <id>` | карточка идеи и история заметок |
| `note <id> "текст"` | заметка без смены статуса |
| `record <id> …` | записать результат WFA вручную |
| `wfa <id> --strategy … --symbol …` | прогнать WFA и записать результат |
| `promote <id>` | пройти ворота и отметить кандидатом |
| `reject <id> --note "…"` | отклонить |
| `log` | перегенерировать журнал |
| `check` | идеи без проверки |

## 2. Консенсус внешних источников (`consensus.py`)

Встречная проверка **своего** входа: если несколько независимых источников
в окне голосуют за ту же сторону — это подтверждение, если против — конфликт.

Что модуль **не делает**:

- не читает каналы и не требует userbot;
- не публикует и не пересылает чужие сигналы и имена источников;
- не влияет на бота, пока `CONSENSUS_ENABLED=0` (по умолчанию).

Что делает: `bot.py` перед публикацией сигнала и `app.publish()` перед
отправкой алерта с TradingView вызывают `consensus.precheck()`. В режиме
`warn` пишет вердикт в консоль, в режиме
`filter` пропускает вход при конфликте. Любая ошибка фильтра — fail-open:
сигнал проходит, бот не замолкает.

### Как сигналы попадают внутрь

Только авторизованно и вручную — с источниками, на которые есть право.

**Проще всего — переслать пост владельцу в premium-бот.** Бот видит источник
пересылки, разбирает текст и отвечает, что записал:

```
✅ XAUUSD LONG · @channel — записано. Учитывается как голос консенсуса.
```

Если канал скрывает автора при пересылке, бот откажет: без атрибуции сигнал
не принимается. Тогда источник указывается вручную:

```
/ext @channel XAUUSD BUY 4020 SL 4005
```

**Скриншот можно просто переслать в premium-бот** — даже если канал нельзя
добавить бота в Discord. Бот скачает картинку, прогонит OCR и поступит так же,
как с текстом: распознал тикер и сторону — записал голос; не распознал —
прислал кнопки LONG/SHORT/пропустить. Источник берётся из пересылки, из
подписи (`#trades`, `@channel`) или помечается `tg:скриншот`. Лучше отправлять
файлом, а не сжатым фото: мелкий текст так читается точнее.

Если на скриншоте **разбор уже закрытой сделки**, добавь в подпись «разбор»
или `#trade` — он уйдёт в архив `discord_trades.jsonl` с меткой win/loss,
а не в голоса консенсуса. Без такой подписи скриншот считается идеей.

Остальные пути:

```
python consensus.py add --source "@channel" --text "XAUUSD BUY 4020 SL 4005 TP 4050"
python consensus.py ingest signals.json
python consensus.py status XAUUSD LONG
```

HTTP-приём (тот же `WEBHOOK_SECRET`, что у `/tv`):

```
POST /consensus/<secret>
{"signals": [{"source": "@channel", "text": "..."}]}
```

Структурированный формат принимается без парсинга текста:

```
{"signals": [{"source": "@channel", "symbol": "XAUUSD", "side": "LONG",
              "entry": 4020, "sl": 4005, "tp": 4050, "ts": 1800000000, "url": "..."}]}
```

Повторный сигнал того же источника по тому же символу и стороне в течение
5 минут не сохраняется: один источник — один голос.

### Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `CONSENSUS_ENABLED` | `0` | включить проверку в боте |
| `CONSENSUS_MODE` | `warn` | `warn` — только лог, `filter` — блокировать конфликт |
| `CONSENSUS_MIN_AGREE` | `2` | сколько независимых источников нужно |
| `CONSENSUS_WINDOW_MIN` | `60` | окно, в котором живёт голос |
| `CONSENSUS_MAX_AGE_MIN` | `240` | старше — не читается |
| `CONSENSUS_SOURCES` | пусто | белый список источников через запятую |
| `CONSENSUS_BLOCK_CONFLICT` | `1` | блокировать ли при конфликте (только `filter`) |
| `CONSENSUS_PATH` | `consensus_signals.jsonl` | хранилище голосов |

## 3. Discord: автоматический приём (`discord_intake.py`)

В Discord официальный Bot API — штатный способ, поэтому здесь автоматизация
возможна без userbot и без скрапинга. Бот слушает только каналы из
`DISCORD_CHANNELS`, разбирает сообщения и скриншоты.

Настройка:

1. Создать приложение в [Developer Portal](https://discord.com/developers/applications),
   добавить бота, включить **Message Content Intent**.
2. Пригласить бота на сервер с правами **View Channels / Read Message History**.
3. В `.env`:

   ```
   DISCORD_INTAKE_ENABLED=1
   DISCORD_TOKEN=...
   DISCORD_CHANNELS=123456789012345678,987654321098765432
   ```

4. Проверить и запустить:

   ```
   python discord_intake.py --check   # конфиг и доступный OCR
   python discord_intake.py           # слушать каналы
   ```

   `start_all.ps1` поднимает процесс сам, если в `.env` есть токен.

Что происходит с сообщением:

| В посте | Что делает бот |
|---|---|
| текст с тикером и стороной | сразу пишет голос в consensus |
| скриншот графика | OCR (`ocr_text.py`) → разбор → голос |
| OCR прочитал, но сторона не ясна | `discord_review.jsonl` + алерт с кнопками **LONG / SHORT / пропустить** |
| нет ни текста, ни сигнала | очередь на проверку, голос не пишется |

Алерт приходит в личку владельцу от premium-бота (его `getUpdates` принимает
нажатия). Одно нажатие подтверждает сторону и записывает голос; «пропустить»
убирает элемент из очереди без записи. Кнопки остаются на месте, если тикер
не распознан — тогда нужен `/ext`. В ежедневном heartbeat владелец видит
строку «Консенсус: N голосов…» и размер очереди; в публичный дайджест
внешние голоса не попадают.

Важно: с обычного скриншота TradingView надёжно читается тикер, а направление
сделки — только если оно есть текстом («Long position», P&L-панель). Если
стороны нет, бот не угадывает и не голосует — пост уходит на ручную проверку.

OCR включается одним пакетом. Он ставится **изолированно** в `.ocr_vendor`,
чтобы не трогать общий userbase с numpy, который использует MT5-часть:

```
python -m pip install --target .ocr_vendor rapidocr-onnxruntime
```

`ocr_text.py` сам добавляет `.ocr_vendor` в путь. Альтернатива —
`pytesseract` + установленный `tesseract` (язык `eng`). Без OCR текст
принимается как обычно, а картинки просто попадают в очередь на проверку.

Проверка распознавания на своём скриншоте:

```
python ocr_text.py chart.png
```

### Ветки: сигналы и разборы

Ветки (threads) — отдельные каналы со своим id, но бот подхватывает их по
родителю: достаточно указать id канала, и сообщения из всех его веток тоже
попадут в обработку. Отдельные id веток нужны только если ветка живёт
отдельно от родителя.

Разборы сделок (профит/убыток) — **не сигналы**: сделка уже закрыта, и
голосовать ею задним числом нельзя. Для них отдельный список:

```
DISCORD_ARCHIVE_CHANNELS=123456789012345678
```

Сообщения оттуда не идут в консенсус, а складываются в `discord_trades.jsonl`:
символ, сторона, `outcome` (win/loss), R, ссылка, автор, текст и OCR. Метка
берётся из заголовка ветки и текста: явное «+2.5R»/«−1R», слова «профит»,
«убыток», «стоп». Это корпус для research — проверять гипотезы на размеченных
примерах, а не принимать решения в моменте.

Собрать историю и посмотреть сводку:

```
python discord_intake.py backfill --channel <id> --threads   # история канала и веток
python discord_intake.py link https://discord.com/channels/<g>/<c>/<m>
python discord_intake.py stats
```

`backfill` берёт 200 сообщений на канал по умолчанию, `--limit` меняет окно,
`--no-ocr` отключает скачивание картинок. Повторный запуск не дублирует
сообщения: ключ — id сообщения.

Ссылку на конкретный разбор можно передать и вручную через `link` — бот сам
скачает сообщение и картинки, без скриншотов. Для этого бот должен быть на
сервере и иметь доступ к каналу.

## Правила

- Источник обязателен и указывается открыто — и в реестре идей, и в записи
  консенсуса.
- Чужие тексты и авторы не публикуются в канале и не уходят подписчикам:
  внешние данные — только внутренний фильтр и повод проверить гипотезу.
- В консенсус попадают лишь публичные или разрешённые автором источники.
- Победа в голосовании не заменяет WFA: консенсус влияет на один вход,
  а не на допуск стратегии.
